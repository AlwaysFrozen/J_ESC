# J_ESC Studio：C++ / Qt 调试上位机

当前已接入高速示波器：七个独立配置页、电机操作页、后台异步 USB、连续/间断采集及 GPU 波形可在同一应用使用。[Python 参考工具](../scope_client/README.md)继续提供独立采集、原始文件记录和 CSV 导出。

完整设计和逐步验证记录见[交接文档](../../docs/host_tool_design.md)，线缆格式见[v2 协议](../../docs/usb_protocol_v2.md)。

## 本机启动

已打包时可直接打开 `build/esc-studio/package/esc_studio.exe`，或双击本目录 `start.bat`。从仓库根目录也可以运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/esc_studio/start.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/esc_studio/start.ps1 -Demo
powershell -NoProfile -ExecutionPolicy Bypass -File tools/esc_studio/start.ps1 -Demo -Scope
```

演示设备在界面明确标注“本地模拟”，不打开串口、不操作电机或 Flash。它用于查看布局和体验读写流程，不能用于证明参数组合有效或算法执行成功。

`-Demo -Scope` 会进入示波器并自动采集本地模拟波形；演示链路的吞吐只用于展示自动策略，不是 USB 测量值。

真实连接要求设备已烧录包含协议 v2 的固件。选择 COM 端口后连接，界面会先查询状态并读取当前配置组。旧文本上位机仍可单独使用；同一个 COM 端口不能同时被两个程序占用。

## 参数配置

- 左侧七页与 `Global_Configs_t` 七个结构体对应，共 166 个可写参数。嵌套字段目前按原 CSV 字段路径展示；搜索匹配名称和说明。
- 整数支持十进制/`0x` 十六进制，浮点支持小数与科学计数。已核对的电机/编码器/控制器/观测器/滤波器枚举使用下拉框，未知值保留显示、不自动改成第一个选项。已知物理量显示单位，嵌套配置支持分组筛选；尚无完整字段依赖联动和折叠树。
- 本地修改先显示为草稿；“写入修改项”只发送当前组已修改项。失败后取消尚未执行的批次，每行显示结果。
- 写 ACK 后自动回读；回读一致才清除草稿。读取设备不会覆盖尚未发送的不同草稿。
- 写入只改变设备 RAM；随后“应用参数”触发固件初始化与校验；持久化须单独“保存 Flash”。Flash 保存采用 10 秒超时，普通请求为 1.5 秒，均不自动重试。
- “应用”及“保存”针对设备 RAM，而非未发送的本地草稿。设备状态限制仍由固件裁决。
- 断线会将设备值标记为未知，并保留本地草稿；重连读取后再次核对。
- 外部字典只允许在断开且没有本地草稿时载入；载入事务失败保留原字典。当前固件尚未提供字典哈希核对，需选择匹配版本。

## 电机操作

提供使能、失能、故障复位、寻相和电阻/电感/极对数/磁链辨识，以及每秒更新的状态。

- 使能不自动启动运动；寻相和辨识单独启动。
- 启动成功不代表完成；结合故障、寻相与辨识阶段判断。
- 失能可排到后台等待队列前面，但不能中断已经执行的请求、Flash 擦写或设备算法中的不可抢占部分。
- 原使能/寻相/辨识命令没有新增断线自动失能语义。下面的新在线运动接口使用独立的 500 ms 心跳租约，超时、退出会话或连接关闭时只停止它所拥有的运动。

### 完整参数方案

“读取全部”读取七组共 166 项配置。“保存方案”将已读取值及本地草稿保存为新的 `.jescconfig`，未读取项不会自动补零。已有文件拒绝覆盖。

“导入 / 比较方案”先完整核对本地字典 SHA256、地址、类型、条目集合和标量数值，再展示相对于当前草稿/已读取值的差异。确认仅载入本地草稿；预览后值或字典变化则拒绝使用旧预览。写入、应用和保存 Flash 仍须显式执行，整套方案不是下位机原子配置事务。

### 基础电流 / 速度 / 位置控制

运动面板按能力位开放；旧固件不显示为可用。电流单位 A；旋转轴的位置/速度为 deg、deg/s，直线轴为 mm、mm/s，加速度与 jerk 分别为轴单位/s²、/s³。速度模式不用额外速度字段；电流模式不用轨迹字段。

- 须设备已使能、校准且寻相完成，无故障/抱闸，配置已应用；不自动使能。禁止与寻相/辨识等其他活动模式混用。
- 每次提交完整目标，拒绝 NaN/Inf、非法轨迹及超出当前电流/速度限制的值；不会分几次覆盖运行变量。
- 前台准备轨迹，高频回调在未嵌套其他中断的边界发布，避免替换被低优先级控制中断更新中的规划器；超过 10 ms 的旧快照拒绝执行。断线取消采用代号检查，不能在准备轨迹期间断线后又重新发布旧目标。
- 界面区分已接收、已生效/保持、位置到达、失败及超时。位置到达后仍保持在线租约，直到显式停止。
- 客户端每 100 ms 发送心跳与查询状态；500 ms 无心跳、离开协议会话或断线将停止在线控制并失能。该软件机制依赖控制 ISR 持续运行，不是硬件急停。
- 当前没有新增统一软件行程边界、自动回零、CST/CSV/CSP 序列接口。真实电机执行、轨迹质量和带载实时性尚未验收；本轮仅在演示设备/测试桩执行运动，在真实板卡查询状态。

## 高速示波器

左侧进入“高速示波器”，选择只读运行变量后开始采集。默认选中三相电流，最多 16 通道；当前板级支持 10/20 kHz，采样发生在下位机高频控制更新后，不依靠桌面定时器采样。

- **自动模式**先测三轮吞吐，取最小值，预留 30% 余量并计入分块开销，再选择连续或间断。
- **连续**边采边传；自动模式出现设备缓存溢出时，排空当前段后转间断。强制连续出现溢出则停止并报告，不静默降低采样率。
- **间断**按目标频率采满一段、冻结上传、重新布防。**单段**始终使用间断模式，上传完整段后停止。
- “停止 / 排空”先停止设备，再核对并收齐最终点数。完整性/序号/时间错误会终止会话，避免继续解释未知的数据流。
- 波形以设备 tick 为时间基准，段间保留真实空隙；低更新率变量在高速采样中可能重复。当前 tick 是控制回调计数，不是独立绝对硬件时钟。
- **滚轮或 ＋/－ 缩放**；**中键拖动**时间轴；“跟随”回到最新数据。
- **左键放 A，右键放 B**，查看原始样本值及 Δt。放置游标会暂停时间轴跟随，但后台采集继续；落在间隙或已淘汰历史中不会插值冒充样本。
- 支持共用 Y 的自动/手动范围，或“分通道坐标”：每通道独立自动 Y，显示已知单位，共用设备时间轴，可滚轮缩放、放置游标并滚动查看通道。当前不做任意单位换算或各通道手动 Y 范围。
- 32 MiB 是带开销预留的滚动历史预算，统计会显示淘汰块数；完整磁盘录制使用独立写盘队列。
- GPU 路径使用 Qt Quick 场景图、三角形曲线和可复用几何缓冲；显示按像素保留极值及顺序，避免简单抽点漏掉尖峰。软件场景图后端明确标注“软件渲染回退”。
- “准备 ms”是包络和绘图数据准备时间，不能当作端到端帧时。当前没有宣称所有电脑、通道数、历史长度均能达到 60 FPS。

采集期间禁止参数编辑/应用/保存等前台操作，仍可优先排队失能并后台读取电机状态。采集开始/停止本身不使能或失能电机。

“FFT / 统计”在后台分析当前时间窗口内最近一段连续有效原始样本，最多 65,536 点，取不超过数据长度的 2 的幂；不足 32 点时报错。不会跨段、丢块、时间缺口或 NaN 拼接。统计包含最小/最大、均值、RMS、峰峰值；FFT 去均值、使用 Hann 窗并按窗增益给出单边幅值、主峰频率和频率分辨率。频谱显示抽取各桶最大值，测量使用全部频点，幅值保持原始单位。

触发、自动从间断恢复连续仍待实现。已在无电机、失能且配置故障状态下验证真实 USB 采集；实际电机负载、全场景 ISR 余量及电机动作尚未验收。硬件记录与 J-Link 复位问题见 [硬件验证](../../docs/hardware_validation.md)。

## 原始录制、回放与导出

- 勾选“采集时录制”，选择新的 `.jescscope` 文件后开始采集；录制包含原始样本、设备 tick、通道、能力、本地字典哈希与每段最终停止状态。
- 磁盘 I/O 在独立线程执行，队列上限为 8 MiB；队列满或磁盘错误会请求停止采集并明确报错，不丢弃数据后继续宣称完整记录。队列预算另有一个在写块及有界元数据开销。
- 写盘期间使用 `.jescscope.partial`；只有正常收尾并刷新成功才重命名成正式文件。已有文件不覆盖；异常 `.partial` 不能作为完整记录回放或导出。
- “打开回放”可在断开设备时使用，也可在连接但停止采集时使用。后台流式核对 CRC、会话、通道类型、配置/段/块序号、设备 tick 和最终点数；失败不会替换当前图。
- 也可用 `esc_studio.exe --replay E:/path/capture.jescscope` 直接打开文件，无需连接设备。
- 回放仍只保留有界显示历史。“回放位置”释放滑块后可载入文件内任意时间窗口；当前通过后台顺序扫描实现，长文件定位耗时随文件长度增长，尚无磁盘索引。段间保持缺口，游标读取原始数据。
- “导出 CSV”从完整文件读取全部原始样本，保留段号、设备 tick、时间及跨段空行；与显示淘汰无关。校验失败不会生成正式 CSV；已有 CSV 拒绝覆盖。
- 与 Python 参考工具共用 `JESCOPE2` 文件格式，已用真实 USB 文件验证双向读取与导出。字典哈希尚未由固件验证；固件尚无可记录的版本查询字段。

测试构建另提供 `scope_probe.exe`：只读使能状态（要求设备失能），然后执行采样/吞吐命令并记录，不发送电机动作命令。其 `--input FILE --csv NEW.csv` 可离线校验与导出；运行需 Qt/MinGW DLL 环境。

`--milliseconds` 支持 1–3,600,000 ms，总超时为请求时长 + 20 秒；已验证无 J-Link 的 65 秒连续记录。当前板卡的 NRST 暂时断开后可独立运行，具体复位电路原因尚未确认。固件 Debug 中的 `od.c` / `od_scope.c` 已单独启用 `-O2`，用于避免 16 通道采样超出 50 μs 预算；重测细节见硬件验证文档。

## 构建与测试

需要本机 C++17 编译器和 Qt 6.5+（本机已验证 6.8.3 MinGW）。Qt 模块：Core、Gui、Quick/QML、QuickControls2、SerialPort；启用测试时另需 Test、QuickTest。桌面工程与 ARM 固件工程独立。

本机开发工具位于 `build/qt-sdk/6.8.3/mingw_64` 和 `build/qt-sdk/Tools/mingw1310_64/bin`：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/esc_studio/build.ps1 -Test -Deploy
```

可使用 `-QtRoot`、`-CompilerBin`、`-BuildDirectory` 指定其他 MinGW SDK/输出目录。脚本仅调整当前进程环境，不改系统 PATH，不自动下载工具。

需要从零安装同版本工具时，可参考本轮使用的 aqt 命令（依赖安装与网络访问按运行环境授权）：

```powershell
python -m pip install --target build/host-tooling aqtinstall==3.3.0
$env:PYTHONPATH = (Resolve-Path build/host-tooling).Path
python -m aqt install-qt windows desktop 6.8.3 win64_mingw -O build/qt-sdk --archives qtbase qtdeclarative qtsvg -m qtserialport
python -m aqt install-tool windows desktop tools_mingw1310 qt.tools.win64_mingw1310 -O build/qt-sdk
```

Qt 核心测试包含标量精度、字典校验和草稿状态、超时与批次失败处理。已有 `build/od-tests/scope_bridge.dll` 时还会执行与真实 C 固件桥的异步互通测试；缺失时明确跳过该项。先运行阶段一完整测试可生成该 DLL：

```powershell
python tests/canopen/run_tests.py --cc E:/MATLAB/R2023b/toolbox/sldrt/clang/win64/clang.exe --lld E:/MATLAB/R2023b/toolbox/sldrt/clang/win64/lld.exe
```

上述编译器路径仅为本机示例。Qt Quick Test 另通过演示设备以键盘和鼠标验证七页切换、编辑/写入/回读/应用、使能失能、保存和断线保留草稿。C 互通测试与演示界面测试分别验证协议和 UI，不能代替真实 USB、电机或 Flash 测试。

采集核心还验证缓存预算、尖峰包络、段间缺口、混合标量、连续停止排空、间断重布防、单段点数、自动模式溢出降级及错误块导致会话终止。界面测试涵盖开始/停止、缩放、A/B 游标和单段。

有 Qt GuiPrivate 开发头时额外构建 `scope_render_tests`，通过 QQuickRenderControl 在隐藏窗口的纹理目标上绘制八通道波形并读回像素。本机已验证 Direct3D 11、AMD Radeon RX 7900 XT；结果在 `build/esc-studio/render-metrics.json` 和 `scope-rhi.png`。该独立离屏循环的 `syntheticFramesPerSecond` 不包括完整 UI、USB 或磁盘写入，不能等同于应用实时帧率。

生产组件使用公开的场景图 API；只有渲染验证程序使用与 Qt 版本绑定的 RHI 开发头。实现依据可参考 [Qt 场景图](https://doc.qt.io/qt-6.8/qtquick-visualcanvas-scenegraph.html)与 [RHI RenderControl 示例](https://doc.qt.io/qt-6.8/qtquick-rendercontrol-rendercontrol-rhi-example.html)。

构建产物与 SDK 均在忽略的 `build/` 中；源代码在本目录。Qt/MinGW 依赖保持各自上游许可。
